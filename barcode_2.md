# 3. BARCODE NUMBER MUST ALWAYS BE UNIQUE

This is a **critical business rule**.

A barcode number must NEVER be duplicated inside the application.

For example:

```text
14378278
```

can belong to only one product/barcode record.

It must not be possible to create:

```text
Product A → 14378278

Product B → 14378278
```

The database must enforce uniqueness using a proper **unique index/constraint**, not only frontend validation.

Frontend validation should provide an early warning, but backend/database constraints must be the final protection.

---

# 4. CUSTOM BARCODE NUMBER

The user must be able to manually provide a custom barcode number.

Example:

```text
Barcode Type: Custom
Barcode Number: 14378278
```

When the user enters it:

1. Validate the number.
2. Check whether it already exists.
3. If it exists, reject it.
4. Show the product currently associated with that number.
5. Allow the user to choose another number.
6. Save only if it is unique.

Example error:

> Barcode `14378278` is already assigned to `2.4 WIRELESS VIDEOGAME BLUE 9503`.

Do not allow duplicate assignment.

# 5. BARCODE TYPE SELECTION

When creating a barcode, allow the user to select the barcode type.

For example:

* Custom
* Code 128
* Code 39
* EAN-13
* EAN-8
* UPC-A
* ITF-14
* QR Code

However, barcode type validation must be different for each symbology.

Do NOT simply allow any arbitrary number for EAN-13, UPC-A, etc.

For standards-based GTIN formats:

* Validate required length.
* Validate numeric requirements.
* Calculate/validate check digit.
* Validate the structure.
* Do not silently convert an arbitrary custom number into a GS1 GTIN.

GS1 specifies that GTIN formats such as GTIN-8, GTIN-12, GTIN-13 and GTIN-14 have defined structures and check digits.

---

# 6. IMPORTANT DISTINCTION — CUSTOM BARCODE VS GS1

The system must clearly distinguish:

### Internal Custom Barcode

Example:

```text
14378278
```

This can be an internal identifier used by this software/business.

### GS1 GTIN / EAN / UPC

These are standards-based identifiers.

Do not claim that an internally generated custom number is a globally unique GTIN.

GS1 states that only GS1-issued GTINs provide uniqueness and verifiability within the GS1 system.

UI should therefore display something like:

```text
Barcode Source
○ Custom / Internal
○ Existing GS1 / EAN / UPC
○ Generate GS1-compatible value
```

If GS1-compatible generation is implemented, require the appropriate company prefix/configuration rather than generating arbitrary GTINs.

# 9. PRODUCT DATA CALCULATION

Do not blindly trust calculated values from the Excel sheet.

For example:

```text
Quantity × Price/Unit = Amount
```

For:

```text
Quantity = 2
Price/Unit = 1499
```

the amount is:

```text
2 × 1499 = 2998
```

The system should calculate this independently.

Similarly, GST calculations should be handled through centralized backend pricing/tax logic.

The frontend should not be the source of truth for financial calculations.

If the imported GST amount differs from the system calculation, flag it.

Example:

```text
GST mismatch

Sheet GST:       ₹285.62
System GST:      ₹285.53

[Use Sheet Value]
[Use Calculated Value]
[Review]
```

The final behavior should follow the application's configured tax/business rules.

# 23. UNIQUE BARCODE RULE — DATABASE LEVEL

Implement:

```text
UNIQUE(barcodeNumber)
```

or the equivalent constraint for the existing database.

Also consider:

```text
UNIQUE(barcodeType, barcodeNumber)
```

only if the business rules require the same number to be valid across separate namespaces.

However, based on the current requirement:

> A single barcode number should always be unique and never repeated.

Therefore, default to a **globally unique barcode number within the application's barcode namespace**.
